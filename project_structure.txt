## 1. PROJECT MISSION
To provide an ultra-reliable, client-side, non-blocking security and forensic sidecar for desktop Microsoft Outlook on Windows. DeskGuard executes real-time heuristic scoring, multi-tier threat intelligence verification, forensic header auditing, and redundant duplicate data cleanup natively through the Outlook MAPI COM interface without server-side dependencies, UI blocking, or data destruction.

## 2. CORE ARCHITECTURE

### A. Single-Writer Multi-Process Model
- **Background Service Process (`--service`):**
  - Sole authorized writer to application storage (`electron-store` on `config.json`, `data.json`, and SQLite `deskguard_vault.db`).
  - Implements atomic pre-write backups (`.bak`) to prevent JSON corruption or file tearing.
  - Hosts a local Windows Named Pipe server (`\\.\pipe\mos_service_<hash>`) protected with per-session token authentication (`MOS_AUTH_<hash>`).
  - Spawns, monitors, and orchestrates the underlying PowerShell engine processes (`currentScanChild` for live/history scans and `psWorker` for auxiliary commands).
  - Listens for scan mode policy updates (`historyScanEnabled`, `deepHistoryScanEnabled`, `onDemandLimit`, `onAccessEnabled`, `threatIntelligenceLevel`) and deterministically debounces engine restarts (500ms) with full configuration synchronization.
  - Expands in-memory cache capacity (`MAX_STATS_PER_CAT = 50000`, `MAX_PROCESSED_IDS = 200000`) ensuring large enterprise mailboxes (100k+ emails) maintain complete detection histories.
- **Client GUI Process:**
  - Operates as a stateless client to the background service.
  - Interacts via the authenticated Named Pipe IPC stream with correlated request-response IDs (`rid`).
  - Synchronously hydrates in-memory caches (`configCache`, `statsCache`, `processedIdsCache`, `releasedFingerprintsCache`) on startup via `loadInitialData()`, backed by SQLite `getAllCategorizedEmails()` fallback to guarantee zero state loss across restarts.
  - Maintains zero-latency UI rendering without direct `electron-store` instantiation in the client.

### B. Outlook STA COM Synchronization, High-Speed Table Extraction & Zero-Leak Lifecycle
- **Recursive BFS Mailbox Queue Crawl:**
  - Employs a `System.Collections.Generic.Queue` to execute a complete Breadth-First Search (BFS) mailbox traversal across all MAPI stores (primary Exchange, PST archives, and secondary mailboxes).
  - Recursively discovers and enqueues all subfolders of subfolders (e.g. `Inbox/Service Security`, `Inbox/Management`, `Sent Items`, and nested folders), overcoming single-level root folder truncation.
  - Automatically filters non-mail containers and respects system exclusions (Deleted Items, Junk Email, Outbox, Drafts) while maintaining full coverage of all user-created mail repositories and Sent Items.
- **High-Speed MAPI Table Extraction (`GetTable`):**
  - Replaces slow, blocking `$f.Items.Item($i)` indexed access with native Outlook MAPI Table cursor extraction (`$f.GetTable()`).
  - Extracts and sorts thousands of `EntryID` references in under 1 second per folder without instantiating heavy COM `MailItem` wrappers.
  - Seamlessly falls back to `GetFirst()` / `GetNext()` enumeration for legacy or non-standard store providers.
  - Emits real-time heartbeats during table traversal, completely eliminating watchdog timeouts on 30k+ item folders.
- **Dynamic Scan Limit & Deep History Decoupling:**
  - In On-Demand mode, checks `$ps.Contains($eid)` to process up to 1,000 new/unscanned items per folder from newest to oldest.
  - In Deep History mode (`deepHistoryScanEnabled = true`), completely bypasses the 1,000 email ceiling to audit all historical emails across every folder and archive.
- **Windows Named Mutex Synchronization (`Global\MOS_Outlook_COM_Lock`):**
  - Microsoft Outlook operates strictly as a Single-Threaded Apartment (STA) COM server.
  - All out-of-process COM calls across `psWorker` and `currentScanChild` acquire the named mutex before issuing MAPI calls, preventing concurrent re-entrant method execution and eliminating `0x8001010A` (`RPC_E_SERVERCALL_RETRYLATER`) and `0x80010001` (`RPC_E_CALL_REJECTED`).
- **Progressive Exponential Backoff & Circuit Breaker:**
  - `Invoke-OutlookMethod` implements backoff delays of `50ms, 150ms, 500ms, 1000ms` with randomized jitter `(10-50ms)`.
  - Automatically trips a 30-second circuit breaker on continuous COM channel saturation to protect the host Outlook process.
- **Strict Zero-Leak COM Hierarchy Traversal:**
  - `Get-TargetFolder-Safe` safely accesses parent stores (`$item.Parent.Store.GetDefaultFolder()`) and deterministically frees intermediate `$parent` and `$store` RCWs in `finally` blocks via `[Runtime.InteropServices.Marshal]::FinalReleaseComObject()`.
  - All attachment collections (`Attachments`), property accessors (`PropertyAccessor`), sender entries (`AddressEntry`), and mail items are explicitly released.
- **Read/Unread State Survival Mandate:**
  - The read/unread status of every mail item is strictly preserved across all scan passes, folder moves, and heuristic evaluations.
  - `Parse-Forensics` captures initial `$item.UnRead` under STA named mutex lock (`Invoke-OutlookMethod`), restores it before returning if reading headers/body altered it, and emits the `unread` boolean.
  - `Robust-Move` captures `$origUnread` prior to `$item.Move()`, and explicitly re-applies `$m.UnRead = $origUnread` prior to calling `$m.Save()`.
  - `Process-Batch` tracks the expected unread state across clean items, moved items, and user-preserved items, enforcing that `$t.UnRead` matches its pre-scan state with automatic verification and restoration.
  - Telemetry and SQLite schema (`unread INTEGER DEFAULT 0`) record and preserve read/unread flags persistently across restarts.
- **User-Relocated Email Non-Interference Protocol:**
  - When an email previously quarantined or flagged by DeskGuard is manually moved by the user in Outlook to another folder, DeskGuard detects its new parent folder via MAPI probing in `Check-Existence`.
  - Probed items are tracked in `$Global:UserMovedFingerprints`.
  - During future sweeps, DeskGuard treats user-relocated items as `action = "User-Preserved"`, skipping move operations to prevent endless quarantine/move loops.
  - The UI displays a prominent red `Moved by User ?` badge with an oversimplified human explanation and a detail banner.
- **Bounded Process Lifecycle & Passive Standby Watcher (`main.js`):**
  - `ensureOutlookRunning()` enforces strict pre-spawn readiness verification via `tasklist`. If Outlook is closed, the scanner process is never spawned, immediately transitioning to passive standby.
  - Bounded exponential retry policy with circuit breaker limits consecutive engine spawn failures to 3 (`MAX_ENGINE_FAILURES`) with exponential backoff delays (4s, 8s, 16s).
  - Tripping the circuit breaker halts process respawns, broadcasts `engine-fault` and `standby: true`, and hands off to the standby watcher.
  - Low-frequency passive watcher polls `tasklist` once every 15 seconds (`15000ms`) with ~0.0% CPU usage. Automatically re-launches scanner and resets failure counter upon detecting `outlook.exe`.
  - 30-second watchdog timeouts route through `requestScannerRestart('watchdog-timeout')`, subject to the unified circuit breaker.

### C. Persistent SQLite Storage Architecture (`vault_db.js`)
- **WAL Mode & High Concurrency:**
  - High-performance SQLite database (`deskguard_vault.db`) running with Write-Ahead Logging (`PRAGMA journal_mode = WAL;`) and `synchronous = NORMAL`.
  - Fast structured queries across millions of emails without JSON serialization limits.
- **Schema & Indexes:**
  - Columns: `id`, `entry_id`, `original_entry_id`, `fingerprint`, `store_id`, `subject`, `sender`, `recipient`, `date`, `time`, `timestamp`, `ip`, `score`, `verdict`, `category`, `tier`, `unread`, `user_moved`, `current_folder`, `created_at`.
  - Dedicated B-Tree indexes on `category`, `score`, `created_at`, `fingerprint`, and `user_moved`.
- **Relocation & Recovery API:**
  - `vaultDB.updateUserMoved(entryId, currentFolder)`: Persists user-relocated mail positions.
  - `vaultDB.getAllCategorizedEmails(limitPerCat)`: Provides startup restoration fallback for `statsCache`.

### D. Virtualized DOM Rendering & Anti-XSS Protection
- **Viewport Virtualization & State Diffing (`ui_list.js`, `ui_duplicates.js`):**
  - Caps active DOM nodes to a fixed viewport window (maximum 50 visible rows) even with categories holding up to 5,000 incident records.
  - Diff-based reconciliation updates only altered cell contents, badges, and scores without rebuilding DOM trees.
- **Strict Anti-XSS Sanitization:**
  - Centralized entity encoding (`window.escapeHtml`) sanitizes all interpolated metadata strings.
  - Plain-text message bodies and header blocks are populated strictly via `element.textContent`, preventing HTML parsing and arbitrary script execution.

### E. Unified IPC Command & Action Routing
- `Quarantine`: Relocates suspect items to **Junk Email** (`olFolderJunk` = 23) or **Deleted Items** (`olFolderDeletedItems` = 3) via `Robust-Move`.
- `Release`: Restores false positives to the **Inbox** (`olFolderInbox` = 6) and registers item fingerprints in `releasedFingerprints` to eliminate re-quarantine loops.
- `Delete`: Permanently purges targeted emails (`$item.Delete()`) with deterministic RCW cleanup.
- `Check-Existence`: Non-blocking item verification via MAPI `GetItemFromID` without throwing COM errors; probes current parent folder to detect user-relocated items.
- `DuplicateScan` & `ResetDuplicateStack`: Drives background mailbox redundancy scanning and manages traversal state.
- `CloudVirusScan`: Deep threat intelligence inspection using DPAPI-decrypted VirusTotal API credentials.
- `app-reset`: Supports both `safe` (re-indexes database, flushes cache, preserves settings and API keys) and `scorched` (wipes all DBs, settings, keys, logs, forensics, and Windows startup run keys).
